# DBackup 系统设计文档

## 1. 设计目标

DBackup 采用“GUI 调度 + 归档引擎 + 仓库接口 + 自动化 + 网络服务”的分层结构。归档、任务配置和仓库格式均由程序内部统一管理，手动、定时、实时和网络任务共享稳定接口。

## 2. 总体架构

```text
Qt 6 Widgets GUI (main.cpp + gui/)
├── 路径选择与参数输入
├── 筛选表达式校验
├── 后台工作线程
└── 日志与结果提示
          │
          ▼
ArchiveService + modular services
├── 目录扫描与元数据采集
├── 筛选匹配
├── 当前 `.abk` 格式序列化与解析
├── zlib 压缩/解压
├── PBKDF2 + AES-256-GCM
├── SHA-256 完整性校验
└── 原子写入与数据还原
          │
          ├── repository/：内容寻址块、加密清单、快照与淘汰
          ├── automation/：Cron、任务持久化、实时目录监控
          ├── network/：远程仓库客户端
          └── server/：TLS REST、Token、SQLite 元数据
```

## 3. 核心数据结构

### FilterOptions

保存路径、名称、扩展名、所有者、类型、尺寸和修改时间范围。空字符串或零表示没有设置相应条件。

### PackOptions

包含压缩等级、可选密码和 `FilterOptions`。

### ArchiveEntry

表示一个文件或目录，包含类型、标志、相对路径、Windows 文件属性、mtime、所有者、原始尺寸和文件内容。

## 4. 模块设计

### 4.1 GUI 模块

`main.cpp` 仅负责初始化 Qt 应用；主窗口使用侧边导航组织概览、备份、恢复、计划、历史、存储与设置。耗时操作在工作线程执行，通过队列调用更新进度和页面，避免跨线程修改控件。

筛选文本由公共函数 `ParseFilterOptions` 解析。验证失败时不创建后台线程，从而避免无效参数被静默忽略。

### 4.2 扫描模块

扫描模块既可将单个文件直接转换为归档条目，也可使用 Unicode Win32 API 遍历目录；目录条目按名称排序以得到稳定的归档顺序。每个条目采集：

- 类型；
- 文件大小；
- 修改时间；
- 所有者名称；
- Windows 文件属性。

无法打开目录或读取文件时返回失败。归档对支持的重解析点保存类型和目标而不递归跟随；未知、危险或不可持久化对象明确拒绝。这样可以防止备份表面成功、实际遗漏数据。

GUI 使用 Qt 6 的 `QFileDialog` 提供原生文件选择体验。备份页通过一个“添加来源”按钮弹出文件或文件夹选项，文件模式支持多选，也可以反复添加；来源列表支持批量移除。多个目录来源会保留各自的根目录名，同名归档路径会被拒绝，避免无提示覆盖。

### 4.3 筛选模块

扫描每个条目时按 AND 关系应用全部已设置条件。目录即使未被归档也会继续递归扫描，以便其子文件仍有机会匹配；还原时会按需创建父目录。

主界面的“配置筛选...”按钮打开模态配置窗口。窗口分别提供路径、名称、扩展名、文件类型、最小/最大尺寸、起止日期和所有者控件，并增加常用类型预设、B/KB/MB/GB 尺寸单位、时间快捷按钮和临时文件/系统缓存/编译输出/日志排除项。“扫描预览”调用 `ArchiveService::preview`，只遍历元数据并统计包含、排除文件数和总大小，不生成归档；“应用”时生成内部表达式并调用公共 `ParseFilterOptions` 校验，成功后在主界面显示只读摘要。“清空”可恢复为无筛选状态。

### 4.4 当前 `.abk` 格式

所有公开打包接口使用同一种归档布局。格式标识仅用于内部完整性判断，不暴露为用户设置；读取端遇到不符合该布局的数据时直接拒绝。

头部：

```text
Magic[6] | Version[2] | Count[4] | Flags[4] | Reserved[4]
```

条目正文：

```text
Type[1] | EntryFlags[1] | PathLength[4] | Path
Attributes[4] | Mtime[8]
OwnerLength[4] | Owner
OriginalSize[8] | StoredSize[8] | Payload
```

正文末尾追加 32 字节 SHA-256。加密时使用 16 字节 Salt、12 字节 Nonce、16 字节认证标签和 AES-256-GCM 密文；不加密时正文仍带 SHA-256。条目包含链接目标和自相对安全描述符。

所有整数以小端序写入。解析器对版本、标志、条目数量、长度、数据大小和正文剩余长度进行检查。

## 5. 备份流程

```text
验证源目录
→ 扫描目录并严格处理 I/O 错误
→ 应用筛选
→ 读取文件与元数据
→ 尝试逐文件压缩
→ 序列化条目
→ 计算 SHA-256
→ 可选加密
→ 写入同目录临时文件
→ 刷新并原子替换目标归档
```

临时文件名包含进程 ID 和线程 ID。任何写入失败都会删除临时文件；只有完整写入成功才通过 `MoveFileExW` 替换目标文件。

## 6. 还原流程

```text
读取归档
→ 验证 Magic、版本和头部
→ 可选解密
→ 验证 SHA-256
→ 解析全部条目
→ 在产生输出前验证所有相对路径
→ 创建目标目录
→ 临时文件写入并原子替换单个文件
→ 恢复 mtime 和 Windows 文件属性
```

先验证所有路径再创建输出，可防止解析到后部恶意路径时目标目录已经产生部分内容。

## 7. 安全设计

- 拒绝以 `/`、`\` 开头的路径；
- 拒绝带盘符冒号的路径；
- 拒绝空组件和 `..`；
- 拒绝未知归档标志；
- 限制条目数量为不超过 10,000,000；
- 使用系统安全随机数生成 Salt 和 Nonce；
- 使用 PBKDF2-SHA256，迭代 100,000 次；
- 对归档正文进行 SHA-256 校验；加密归档还必须通过 GCM 标签验证；
- 不跟随源目录重解析点。

归档和增量块使用 AES-256-GCM。恢复会校验相对路径并拒绝通过重解析点逃逸目标根目录。

## 8. 错误处理

核心 API 使用 `bool` 表示成功状态，并通过 `error` 返回面向用户的中文错误。调用方不得忽略失败状态。主要错误类别包括：

- 源目录不存在；
- 文件或目录不可读；
- 不支持的重解析点；
- 压缩、加密或哈希失败；
- 归档格式、长度或校验错误；
- 临时文件创建、写入或替换失败；
- 属性或时间恢复失败。

## 9. 测试设计

测试使用 Google Test，通过临时测试目录隔离数据。测试包括归档往返、无效格式拒绝、异常输入、压缩加密、筛选校验、篡改检测、属性恢复和原子替换。localhost 网络集成、Qt offscreen、权限、双机和发布包属于下一层测试。详细结果见 `docs/test-report.md`，需求覆盖关系见 `docs/traceability-matrix.md`。

## 10. 已知限制与演进方向

1. 文件和归档正文仍整体加载到内存，不适合超大文件。
2. 归档在 Windows 上保存并恢复 owner、group 和 DACL；符号链接所指对象的 ACL 不经链接间接修改。没有相应权限时恢复会明确失败或给出错误。
3. GUI 已采用结构化筛选控件；后续可继续增加可排序的自定义规则列表和原生日历控件。
4. 解包不是整个目录级事务，单个文件是原子写入，但多文件中途失败仍可能产生部分结果。
5. Qt 6.8.3 GUI 与服务器已完成 Release 构建和 localhost TLS 联调；跨机器发布、真实证书链及长期后台运行仍需独立验收。

## 11. 构建与发布设计

- 构建脚本仅使用与 Qt MinGW kit 匹配的 zlib；缺少头文件或静态库时明确失败，不联网下载依赖。
- Google Test 源码随仓库提供，不需要构建机再次下载。
- `build.bat package` 通过 CPack 和 Qt 部署工具生成 ZIP，输出到 `out/package/DBackup-portable.zip`；包中包含 Qt、匹配的 MinGW 运行库、SQLite 插件及 OpenSSL 3 TLS 运行库。
- 支持的自动构建入口面向 Windows x64、Qt MinGW kit；构建目录位于 `out/build-release` 和 `out/build-test`。

## 12. 目标模块边界与重构原则

```text
GUI 页面 -> 应用服务/统一任务执行器 -> IBackupRepository/ArchiveService
                                           |-> archive：扫描、格式、压缩、加密、元数据、恢复
                                           |-> repository：块、清单、快照、保留
                                           |-> automation：Cron、调度、Watcher
                                           |-> network：REST、TLS 信任、远程仓库
服务端路由 -> 认证服务 -> 快照服务 -> SQLite 元数据 + 原子块存储
```

- `ArchiveService` 是归档稳定入口；`core/` 集中操作上下文和 Windows CNG 加密原语，归档与增量仓库复用同一实现。
- GUI 不读取私有清单、不遍历块目录、不执行 SQL，只调用稳定服务接口。
- 手动、定时、实时和远程任务复用统一执行器及 `OperationContext`。
- 路径校验、哈希、原子文件和元数据工具只能保留一个规范实现。
- 公共数据结构必须带格式/配置版本；当前发行版只解析指定的当前版本，格式更新时要求重新创建数据，不执行历史迁移。

## 13. 跨模块关键流程

### 13.1 自动任务

```text
Cron/Watcher 触发 -> 运行锁 -> 读取凭据 -> 统一执行器
-> 成功提交归档/快照 -> 更新最近结果 -> 执行保留策略 -> 计算下次运行
```

失败或取消不得进入保留淘汰阶段；运行中再次触发只记录一次待运行请求。

### 13.2 远程上传

```text
本地成功快照 -> 解析待传块集合 -> 批量查询当前用户缺块
-> 逐块上传/重试 -> 服务端原子保存 -> 事务提交快照 -> GUI 显示成功
```

快照提交是唯一可见性边界。取消或断网可以留下无引用块以便续传，但不能产生不完整快照。

### 13.3 远程恢复

```text
获取用户快照 -> 检查本地缓存 -> 下载缺块到临时文件
-> 验证块格式/GCM/明文 SHA-256 -> 原子进入缓存
-> 验证并安装清单 -> LocalRepository 恢复 -> 独立比较
```

仅按文件是否存在复用缓存是不充分的；复用前必须验证。

## 14. 服务器数据与事务

建议 schema 责任如下：

| 表 | 关键字段 | 约束 |
|---|---|---|
| `users` | id、username、salt、password_hash | username 唯一，禁止明文密码 |
| `tokens` | token_hash、user_id、expires_ms | 只存哈希，过期/注销不可用 |
| `snapshots` | id、user_id、created_ms、manifest | `(user_id,id)` 唯一 |
| `snapshot_chunks` | snapshot、hash、顺序 | 外键或等价事务约束 |
| `chunks` | user_id、hash、size、ref_count | 去重只在单用户范围 |

提交快照与增加引用必须在一个事务内；删除快照与减少引用也必须在一个事务内。块文件删除可在事务后进行，但启动维护任务必须能清理数据库中引用为零的遗留块和超时临时文件。

## 15. 安全威胁与控制

| 威胁 | 控制 |
|---|---|
| 归档路径穿越 | 规范化相对路径、拒绝盘符/绝对/`..`、检查目标路径链重解析点 |
| 篡改/错误密码 | AES-GCM 标签、SHA-256、任何失败立即中止 |
| 凭据泄漏 | Credential Manager、Token 哈希、日志脱敏 |
| 跨用户读取 | 所有块和快照查询强制用户作用域 |
| TLS 中间人 | 首次指纹确认、后续固定、变化阻止、其他 TLS 错误不忽略 |
| 资源耗尽 | 请求体、块、数组、条目、路径和分页上限 |
| 清理误删 | 引用事务、只删 ref_count=0、独立一致性扫描 |
| 半成品可见 | 临时文件、原子替换、清单最后提交 |

## 16. 设计完成检查

每个模块交付前检查：接口是否稳定、失败是否传播、取消是否贯穿、临时资源是否清理、秘密是否泄漏、是否有边界测试、用户文档是否一致。详细开发顺序见 `development-guide.md`。

# DBackup 系统设计文档

## 1. 设计目标

DBackup 采用“GUI 调度 + 独立归档引擎”的结构。设计重点是保持归档格式稳定、支持 v1/v2 兼容、在失败时避免损坏已有备份，并为后续功能保留扩展空间。

## 2. 总体架构

```text
Qt 6 Widgets GUI (main.cpp + gui/)
├── 路径选择与参数输入
├── 筛选表达式校验
├── 后台工作线程
└── 日志与结果提示
          │
          ▼
Packer compatibility API + modular services
├── 目录扫描与元数据采集
├── 筛选匹配
├── v1/v2 序列化与解析
├── zlib 压缩/解压
├── PBKDF2 + AES-256-CBC
├── SHA-256 完整性校验
└── 原子写入与数据还原
          │
          ├── repository/：内容寻址块、加密清单、快照与淘汰
          ├── automation/：Cron、任务持久化、实时目录监控
          ├── network/：远程仓库客户端
          └── server/：TLS REST、Token、SQLite 元数据
```

## 3. 核心数据结构

### FilterOptions

保存路径、名称、扩展名、所有者、类型、尺寸和修改时间范围。空字符串或零表示没有设置相应条件。

### PackOptions

包含压缩等级、可选密码和 `FilterOptions`。

### ArchiveEntry

表示一个文件或目录，包含类型、标志、相对路径、Windows 文件属性、mtime、所有者、原始尺寸和文件内容。

## 4. 模块设计

### 4.1 GUI 模块

`main.cpp` 仅负责初始化 Qt 应用；`gui/MainWindow` 使用侧边导航和堆叠页面组织概览、备份、恢复、计划、历史、存储与设置。当前备份和恢复页面接入真实能力，其余页面以明确的规划状态预留扩展边界。用户触发耗时操作后，GUI 创建工作线程，后台线程只调用 `Packer`，完成后通过 Qt 队列调用更新界面，避免跨线程直接修改控件。

筛选文本由公共函数 `ParseFilterOptions` 解析。验证失败时不创建后台线程，从而避免无效参数被静默忽略。

### 4.2 扫描模块

扫描模块既可将单个文件直接转换为归档条目，也可使用 Unicode Win32 API 遍历目录；目录条目按名称排序以得到稳定的归档顺序。每个条目采集：

- 类型；
- 文件大小；
- 修改时间；
- 所有者名称；
- Windows 文件属性。

无法打开目录、无法读取文件或发现重解析点时返回失败。这样可以防止备份表面成功、实际遗漏数据。

GUI 使用 Qt 6 的 `QFileDialog` 提供原生文件选择体验。备份页通过一个“添加来源”按钮弹出文件或文件夹选项，文件模式支持多选，也可以反复添加；来源列表支持批量移除。多个目录来源会保留各自的根目录名，同名归档路径会被拒绝，避免无提示覆盖。

### 4.3 筛选模块

扫描每个条目时按 AND 关系应用全部已设置条件。目录即使未被归档也会继续递归扫描，以便其子文件仍有机会匹配；还原时会按需创建父目录。

主界面的“配置筛选...”按钮打开模态配置窗口。窗口分别提供路径、名称、扩展名、文件类型、最小/最大尺寸、起止日期和所有者控件，并增加常用类型预设、B/KB/MB/GB 尺寸单位、时间快捷按钮和临时文件/系统缓存/编译输出/日志排除项。“扫描预览”调用 `Packer::preview`，只遍历元数据并统计包含、排除文件数和总大小，不生成归档；“应用”时生成内部表达式并调用公共 `ParseFilterOptions` 校验，成功后在主界面显示只读摘要。“清空”可恢复为无筛选状态。

### 4.4 v1 格式

v1 用于向后兼容，结构为 20 字节头部和顺序条目：

```text
Magic[6] | Version[2] | Count[4] | Reserved[8]
Entry = Type | Path | Attributes | Mtime | DataSize | Data
```

### 4.5 v2/v3 格式

v2 头部：

```text
Magic[6] | Version[2] | Count[4] | Flags[4] | Reserved[4]
```

条目正文：

```text
Type[1] | EntryFlags[1] | PathLength[4] | Path
Attributes[4] | Mtime[8]
OwnerLength[4] | Owner
OriginalSize[8] | StoredSize[8] | Payload
```

正文末尾追加 32 字节 SHA-256。v2 加密归档继续使用 16 字节 Salt、16 字节 IV 和 AES-CBC；新写入的 v3 使用 16 字节 Salt、12 字节 Nonce、16 字节认证标签和 AES-256-GCM 密文。v3 条目还增加链接目标和自相对安全描述符。

所有整数以小端序写入。解析器对版本、标志、条目数量、长度、数据大小和正文剩余长度进行检查。

## 5. 备份流程

```text
验证源目录
→ 扫描目录并严格处理 I/O 错误
→ 应用筛选
→ 读取文件与元数据
→ 尝试逐文件压缩
→ 序列化条目
→ 计算 SHA-256
→ 可选加密
→ 写入同目录临时文件
→ 刷新并原子替换目标归档
```

临时文件名包含进程 ID 和线程 ID。任何写入失败都会删除临时文件；只有完整写入成功才通过 `MoveFileExW` 替换目标文件。

## 6. 还原流程

```text
读取归档
→ 验证 Magic、版本和头部
→ 可选解密
→ 验证 SHA-256
→ 解析全部条目
→ 在产生输出前验证所有相对路径
→ 创建目标目录
→ 临时文件写入并原子替换单个文件
→ 恢复 mtime 和 Windows 文件属性
```

先验证所有路径再创建输出，可防止解析到后部恶意路径时目标目录已经产生部分内容。

## 7. 安全设计

- 拒绝以 `/`、`\` 开头的路径；
- 拒绝带盘符冒号的路径；
- 拒绝空组件和 `..`；
- 拒绝未知归档标志；
- 限制条目数量为不超过 10,000,000；
- 使用系统安全随机数生成 Salt 和 IV；
- 使用 PBKDF2-SHA256，迭代 100,000 次；
- 对 v2 正文进行 SHA-256 校验；
- 不跟随源目录重解析点。

当前限制：AES-CBC 不是认证加密模式，目的目录中预先存在的重解析点也需要在后续版本进一步防御。生产级版本建议采用 AES-GCM 并校验目的路径的最终解析位置。

## 8. 错误处理

核心 API 使用 `bool` 表示成功状态，并通过 `error` 返回面向用户的中文错误。调用方不得忽略失败状态。主要错误类别包括：

- 源目录不存在；
- 文件或目录不可读；
- 不支持的重解析点；
- 压缩、加密或哈希失败；
- 归档格式、长度或校验错误；
- 临时文件创建、写入或替换失败；
- 属性或时间恢复失败。

## 9. 测试设计

测试使用 Google Test，通过临时测试目录隔离数据。测试包括核心往返、异常输入、格式兼容、压缩加密、筛选校验、篡改检测、属性恢复和原子替换。详细结果见 `docs/test-report.md`。

## 10. 已知限制与演进方向

1. 文件和归档正文仍整体加载到内存，不适合超大文件。
2. v3 在 Windows 上保存并恢复 owner、group 和 DACL；符号链接所指对象的 ACL 不经链接间接修改。没有相应权限时恢复会明确失败或给出错误。
3. GUI 已采用结构化筛选控件；后续可继续增加可排序的自定义规则列表和原生日历控件。
4. 解包不是整个目录级事务，单个文件是原子写入，但多文件中途失败仍可能产生部分结果。
5. Qt 6.8.3 GUI 与服务器已完成 Release 构建和 localhost TLS 联调；跨机器发布、真实证书链及长期后台运行仍需独立验收。

## 11. 构建与发布设计

- CMake 优先通过 `find_package(ZLIB)` 使用系统 zlib。
- 找不到 zlib 时，默认通过 `FetchContent` 下载固定版本 zlib 1.3.1；可用 `DBACKUP_FETCH_ZLIB=OFF` 禁止联网回退。
- Google Test 源码随仓库提供，不需要构建机再次下载。
- 发布由 `windeployqt` 携带 Qt、MinGW、SQLite 插件及 TLS 后端；服务器使用 PEM 私钥时还需 OpenSSL 3 运行库。
- `cmake --build build --target package` 使用 CPack 生成 ZIP；压缩包项目名为 DBackup，可执行文件名保持 `BackupTool.exe`。
- CMake 明确限制平台为 Windows；支持 MinGW，并为 MSVC/zlib CMake 目标保留兼容路径。

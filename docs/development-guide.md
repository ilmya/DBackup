# DBackup Sprint 1-5 完整开发指导

## 1. 文档定位

本文把课程要求转换为可执行的开发路线。功能定义以 `requirements.md` 为准，模块责任以 `design.md` 为准，验收编号以 `traceability-matrix.md` 和 `acceptance-test-cases.md` 为准。

课程要求最终交付一款基本可用的数据备份软件、需求说明、系统设计、测试报告、源码、可执行程序和构建脚本；评价重点是正确性、易用性、健壮性、文档一致性、源码质量、项目演示和答辩。Sprint 1-5 是增量路线，最终版本必须保持所有前序功能可用。

## 2. 课程计分与项目范围

| 能力 | 课程分值 | DBackup 目标 |
|---|---:|---|
| 数据备份/还原 | 基础分共 40 | 多来源备份、安全恢复、失败不破坏有效版本 |
| 特殊文件类型 | 10 | 符号链接、Junction、硬链接；管道/设备安全拒绝 |
| 文件元数据 | 10 | owner、group、DACL、mtime、Windows 属性 |
| 自定义备份 | 3 x 6 | 路径、类型、名字、时间、尺寸、用户 |
| 打包解包 | 每种方案 10 | 自定义 `.abk` 归档 |
| 压缩/加密 | 每种算法各 10 | zlib、AES-256-GCM |
| 图形界面 | 10 | Qt 6 Widgets 完整操作闭环 |
| 定时/实时 | 10 / 15 | Cron、保留策略、`ReadDirectoryChangesW` |
| 网盘/用户/元数据/传输 | 10 / 5 / 5 / 5 | HTTPS C/S、Token、SQLite、TLS |
| 增量备份 | 5 | 4 MiB 内容寻址块、快照、去重 |

课程指出扩展功能若由第三方库或程序直接实现，可能只计原分值的 50%。答辩应区分第三方提供的压缩/密码原语，与团队自主完成的格式、流程、原子提交、错误处理、GUI 集成和测试，并提前确认计分口径。

## 3. 统一工程规则

### 3.1 开始条件（Definition of Ready）

任务进入编码前应具备需求编号、输入输出、正常/失败流程、接口或格式契约、成功与失败测试，并记录尚未确认的课程口径。

### 3.2 完成条件（Definition of Done）

功能只有在以下项目全部满足后才算完成：

1. 行为符合需求且未破坏前序 Sprint；
2. 自动测试通过，不能自动化的场景有人工步骤；
3. 错误、取消、清理和重启路径已验证；
4. GUI 可实际到达，文案面向用户；
5. 用户文档、设计、测试用例同步更新；
6. `build.bat test`、验收工具自测和 `git diff --check` 通过；
7. 有报告、日志或截图证据。

### 3.3 协作与版本控制

- 一个提交只完成一个可说明目标，使用 `feat:`、`fix:`、`test:`、`docs:` 或 `refactor:`。
- 功能分支开发后合并，主分支保持可构建；Sprint 评审必须现场恢复数据。
- 不提交构建目录、测试数据、归档、证书私钥、Token、密码或服务器数据库。
- 每个 Sprint 回顾至少产生一项下一阶段可执行改进，避免只写工作流水账。

## 4. Sprint 1：核心骨架与本地打包

目标：完成“选择来源 -> 单个归档 -> 恢复 -> 独立比较”闭环。

实现顺序：

1. 定义归档 Magic、版本、标志、条目和长度上限；确定 UTF-8 路径与小端整数。
2. 实现 Unicode 扫描、多来源根目录、空目录、冲突检查和严格错误传播。
3. 使用同目录临时文件、刷新和原子替换写归档。
4. 恢复前验证全部路径；文件临时写入，目录元数据最后恢复。
5. 建立 Qt 来源列表、目标选择、备份/恢复后台任务和取消入口。
6. 覆盖空文件、边界尺寸、嵌套、Unicode、同名冲突、目标在来源内和恶意归档。

发行策略：`.abk` 只有一种程序内部格式，不向用户暴露格式版本。测试归档和验收数据统一由当前构建重新生成，不增加格式迁移或多格式选择功能。所有公开打包入口必须写入相同布局。

关键决策：多个来源产生相同归档路径时拒绝；目标和临时文件必须从扫描排除；任何不可读项导致整体失败，不能伪装完整。

完成判据：执行 `S1-PACK-*`、`S1-RESTORE-*`、`S1-GUI-*`，独立比较路径、SHA-256、空目录、mtime 和属性。

## 5. Sprint 2：压缩、加密和六类筛选

目标：让归档更小、更安全，并允许用户准确选择备份集合。

实现顺序：

1. 为条目增加压缩标志、原始长度和存储长度；仅在结果更小时保存压缩数据。
2. 将完整正文纳入 AES-256-GCM 认证；先测试错误密码和篡改，再接 GUI。
3. 建立独立 `FilterOptions`，让预览和实际备份共用同一个匹配器。
4. 路径、类型、名称、时间、尺寸、用户跨类别按 AND；多扩展名按 OR。
5. 明确日期时区和包含边界，拒绝非法日期、负数、溢出和矛盾范围。

目录自身不匹配时仍可继续扫描子项。密码不得进入日志，错误密码不得留下成功输出。

完成判据：执行 `S2-COMP-*`、`S2-CRYPT-*`、`S2-FILTER-*`。随机数据不要求压缩变小，只要求正确恢复。

## 6. Sprint 3：高级文件与自动化

目标：从手动工具演进为后台自动保护软件。

高级文件实现顺序：

1. 用重解析点 API 区分文件/目录符号链接和 Junction，扫描不跟随。
2. 保存链接目标、属性、mtime 和自相对安全描述符。
3. 普通内容完成后创建安全链接，再恢复目录时间、属性和 ACL。
4. 用文件 ID 建立硬链接组；拒绝绝对/逃逸链接和穿越已有重解析点的恢复路径。
5. 活动命名管道和设备对象明确拒绝，不伪装成普通文件。

自动化实现顺序：

1. 定义带版本号的 `BackupJob` JSON 当前 schema；读取器只加载当前 schema，不迁移旧配置；密码只存 Credential Manager。
2. 完成 Cron、下次运行、可注入时钟和同任务运行锁。
3. 手动、计划和实时任务调用同一个执行器；只在成功提交后淘汰旧版本。
4. 实时监控实现 3 秒防抖、30 秒最长等待、输出排除、溢出重扫和目录丢失重试。
5. 完成托盘暂停/继续/立即运行/退出及可选登录启动。

当前重点差距：公共模型尚无明确硬链接组字段；需验证监控溢出重扫和目录丢失重试；计划页应支持完整编辑而非仅依次弹框创建；需测试失败任务不触发淘汰。

完成判据：执行 `S3-META-*`、`S3-CRON-*`、`S3-REALTIME-*`、托盘和登录启动用例。权限不足应记 `BLOCKED/SKIP`，不能记 `PASS`。

## 7. Sprint 4：网络版转型

目标：建立受信局域网内可演示的 HTTPS 客户端/服务器闭环。

实现顺序：

1. 冻结 `/api/v1` 请求、响应、状态码、分页和大小上限。
2. 实现 SQLite schema 迁移、PBKDF2 密码哈希、Token 哈希、过期和注销。
3. 实现用户作用域块检查、原子上传、下载和快照事务提交。
4. 实现列表、详情、删除、引用计数和无引用块回收。
5. 强制 TLS；实现首次指纹确认、重复连接和证书变化拒绝。
6. 客户端串联“查询缺块 -> 上传缺块 -> 提交快照”和远程恢复。
7. 先做 localhost 临时证书集成测试，再做双机验收。

一致性规则：块落盘成功后才记数据库；快照事务成功后才增加引用；所有资源查询带用户作用域；启动时清理过期 Token、临时文件并审计数据库和块目录。

当前重点差距：需验证分页与所有上限、Token/临时文件清理和启动一致性检查；下载块在缓存前必须验证格式、GCM 和明文 SHA-256；证书测试需覆盖过期和主机名错误；远程历史需补充详情、容量和搜索证据。

完成判据：执行 `S4-TLS-*`、`S4-AUTH-*`、`S4-REMOTE-*`。至少完成 localhost 闭环；双机环境不足时标 `BLOCKED`。

## 8. Sprint 5：增量、续传和产品完善

目标：只处理变化数据，提供可取消、可恢复、可解释的体验。

实现顺序：

1. 定义唯一当前仓库配置、清单和块格式；每仓库独立 Salt，格式不匹配时拒绝加载并要求新建仓库，不迁移旧数据。
2. 保存上一快照索引，先以 size + mtime 判断，变化文件再按 4 MiB 分块。
3. 块和清单使用 AES-256-GCM；原子发布清单，取消不发布快照。
4. 实现安全删除、引用扫描/计数和保留策略预览。
5. 上传查询缺块；下载校验后缓存，重试复用已验证块。
6. 统一 `OperationContext` 贯穿扫描、归档、恢复、快照、上传和下载，提供速度和 ETA。
7. 历史页完成搜索、详情、按版本恢复、删除和清理。

当前重点差距：需确认本地仓库是否真正实现 size + mtime 快速路径；`listSnapshots` 应解密清单获得真实统计；下载时已有块和新块都必须验证；取消、损坏块、缺块和引用清理覆盖仍需扩充；大文件路径仍需流式化和压力验证。

完成判据：执行 `S5-INCR-*`、`S5-RESUME-*`、`S5-PROGRESS-*`、`S5-HISTORY-001`，以块数量和物理大小证明去重。

## 9. 目标模块边界

```text
core/          操作上下文、进度、取消、公共错误
archive/       扫描、格式、压缩、加密、元数据和恢复
repository/    内容寻址块、清单、快照、保留和仓库接口
automation/    Cron、任务配置、调度、监控和统一执行器
network/       REST 客户端、证书信任和远程仓库适配器
server/        HTTPS 路由、认证、SQLite、块存储和维护
gui/           页面、对话框、视图模型和统一进度
security/      Credential Manager 和敏感数据处理
tests/         单元、组件和 localhost 集成测试
tools/acceptance/ 独立于产品的验收数据与比较器
```

`ArchiveService` 是归档的稳定 API；`core/` 集中公共操作上下文和 CNG 加密原语，归档与仓库通过稳定接口调用。GUI 不得直接解析清单、遍历块目录或操作 SQLite。

## 10. 测试策略

| 层级 | 主要内容 | 执行时机 |
|---|---|---|
| 单元 | 路径、Cron、筛选、格式、加密、哈希、引用规则 | 每次提交 |
| 组件 | `.abk` 往返、仓库、Watcher、数据库事务 | 每次合并 |
| localhost 集成 | TLS、认证、缺块、提交、恢复、删除 | 网络变更后 |
| GUI offscreen | 页面、导航、校验、取消、发布文案 | 每次发布 |
| 独立验收 | 标准数据、恢复比较、权限、链接、服务器 | Sprint 评审 |
| 双机人工 | 防火墙、证书、断网续传、便携包 | 最终验收 |

自动结果写入 `test-report.md`，人工结果填写 `acceptance-test-cases.md`。FAIL、SKIP、BLOCKED 必须分别记录。

## 11. 发布前清单

1. `cmd.exe /c build.bat test` 和验收工具 `self-test` 无失败。
2. `.abk`、本地增量、计划/实时和远程闭环按编号执行。
3. `build.bat package` 成功，ZIP 在无 Qt/编译器电脑可启动。
4. 用户可见字符串不含占位、Sprint、待开发、测试数量或内部诊断。
5. 发布包不含测试数据、私钥、数据库、凭据和工程专用文档。
6. 需求-设计-测试矩阵没有未解释的 P0/P1 空项。
7. 答辩演示至少覆盖：正常恢复、错误密码/篡改、筛选、自动化、增量和远程隔离。

## 12. 风险优先级

| 优先级 | 风险 | 处理 |
|---|---|---|
| 最高 | 文档宣称超过实现 | 仅以测试证据更新状态，不用“已支持”代替结果 |
| 最高 | 恢复路径逃逸或错误成功提示 | 统一先校验后输出，检查每个 I/O 返回值 |
| 高 | 用户隔离/TLS 信任错误 | 双用户、越权、指纹变化集成测试 |
| 高 | 清理误删共享块 | 原子清单、引用测试，只在副本做破坏测试 |
| 高 | 自动任务重复或误淘汰 | 注入时钟、运行锁、成功后淘汰 |
| 中 | 超大文件内存占用 | 流式处理及 512 MiB/1 GiB 压力用例 |
| 中 | 第三方库影响计分 | 答辩前确认并展示自主实现部分 |

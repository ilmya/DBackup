# DBackup 需求分析说明书

## 1. 文档目的

本文档定义 DBackup 数据备份软件 Sprint 1 和 Sprint 2 的功能范围、质量要求与验收标准。Sprint 3 之后的定时、实时、网络和增量备份不属于当前版本。

## 2. 项目背景

DBackup 是面向 Windows 10/11 的本地数据备份工具。用户可将多个文件和文件夹组合保存为单个 `.abk` 文件，并在需要时恢复目录结构、文件内容和部分元数据。项目使用 C++17、Win32 API、CMake、zlib、Windows CNG 和 Google Test。

## 3. 用户与使用场景

主要用户是希望手工备份本地资料的普通 Windows 用户。

典型场景：

1. 用户选择一个或多个资料文件、文件夹和 `.abk` 保存位置，生成本地备份。
2. 用户输入密码，生成压缩且加密的备份文件。
3. 用户通过扩展名、路径、大小或日期排除不需要的数据。
4. 用户选择 `.abk` 文件和目标目录，恢复备份内容。

## 4. 功能需求

### FR-01 备份来源与目录扫描

- 系统应允许在一个备份任务中添加多个普通文件和文件夹。
- “添加来源”按钮应提供文件和文件夹两种入口；文件和文件夹选择均支持多选。
- 系统应递归扫描普通文件和目录。
- 系统应保留相对目录结构。
- 遇到无法访问的目录、无法读取的文件或重解析点时，系统应终止备份并给出错误，不得静默生成不完整备份。

### FR-02 打包备份

- 系统应将选中的目录树写入单个 `.abk` 文件。
- 归档应包含 Magic、版本、条目数量和条目数据。
- 归档写入应先写临时文件，完整成功后替换目标文件。
- 写入失败时不得以损坏文件覆盖原有有效备份。

### FR-03 数据还原

- 系统应支持 v1、v2 两种归档格式。
- 系统应恢复普通文件、目录、文件内容、修改时间和可恢复的 Windows 文件属性。
- 系统应拒绝绝对路径、盘符路径、空路径和含 `..` 的路径。
- 单个文件应通过临时文件写入并原子替换。

### FR-04 压缩

- v2 归档应使用 zlib 尝试压缩每个非空文件。
- 仅当压缩结果小于原始数据时才保存压缩结果。
- 解压后应校验恢复数据的长度。

### FR-05 密码保护

- 用户可选择是否设置密码。
- 设置密码后，系统使用 PBKDF2-SHA256 派生 256 位密钥，并使用随机 Salt、IV 和 AES-256-CBC 加密归档正文。
- 系统应通过 SHA-256 检测错误密码、损坏或篡改。
- 密码为空时生成未加密 v2 归档。

### FR-06 自定义筛选

GUI 应提供独立的可视化筛选配置窗口，不要求用户记忆或手写表达式。面板至少包含路径、类型、名称、时间、尺寸和用户六类条件，并在应用前检查格式和范围。类型提供常用文件类别预设，尺寸可选择 B/KB/MB/GB，时间提供今天、最近 7 天和最近 30 天快捷项，并提供临时文件、系统缓存、编译输出和日志文件的常用排除选项及扫描预览。

筛选表达式由分号分隔的 `key=value` 组成，支持：

| 键 | 含义 | 示例 |
|---|---|---|
| `path` | 相对路径包含指定文本 | `path=docs` |
| `name` | 名称包含指定文本 | `name=report` |
| `ext` | 文件扩展名 | `ext=.txt` |
| `type` | `file` 或 `dir` | `type=file` |
| `minsize` | 最小字节数 | `minsize=1024` |
| `maxsize` | 最大字节数 | `maxsize=10485760` |
| `after` | 不早于指定日期 | `after=2026-01-01` |
| `before` | 不晚于指定日期当天 | `before=2026-12-31` |
| `owner` | 所有者名称包含文本 | `owner=alice` |

未知键、非法数字、非法日期、错误类型和矛盾范围应在操作开始前提示用户。

### FR-07 图形界面

- GUI 应包含备份和还原两个标签页。
- 用户可通过现代 Windows 系统对话框选择多个文件或文件夹，并在列表中移除来源。
- 密码输入应隐藏字符。
- 筛选条件应通过“配置筛选”窗口填写，并在主界面显示当前筛选摘要。
- 操作应在后台线程执行，完成后在日志区显示结果。
- 必填路径未选择时，操作按钮应不可用。

### FR-08 兼容性

- 旧接口生成的 v1 归档应继续可读。
- 新功能使用 v2 格式，不改变 v1 解析规则。

## 5. 非功能需求

### 正确性

- 恢复后的文件内容应与源文件逐字节一致。
- 错误或损坏归档不得被当作有效归档恢复。

### 健壮性

- I/O 错误必须返回明确错误信息。
- 不得静默跳过无法读取的数据。
- 临时文件应在失败后清理。

### 易用性

- README 应提供构建、使用、筛选和测试说明。
- 错误信息应指出失败对象和原因类别。

### 安全性

- 解包不得写出目标目录。
- 密码密钥应使用随机 Salt 和足够次数的 PBKDF2。
- 当前 AES-CBC + 加密正文内 SHA-256 是课程阶段方案；后续发布版本建议升级 AES-GCM。

### 可维护性

- 核心归档逻辑与 GUI 分离。
- 使用自动化测试保护 v1/v2 兼容性和核心行为。

## 6. 数据与元数据范围

当前版本支持普通文件和目录，不支持符号链接、目录联接等重解析点。修改时间和 Windows 文件属性会被恢复；所有者名称会被记录并可用于筛选，但由于恢复属主通常需要额外系统权限，当前版本不恢复所有者。ACL 权限也不在 Sprint 1/2 范围内。

## 7. 验收标准

1. 项目能在 Windows + MinGW 环境使用 CMake 构建。
2. 普通文件、空文件、二进制文件和嵌套目录能完成备份还原。
3. v1/v2 归档均能读取。
4. 压缩、加密、错误密码和筛选场景通过自动化测试。
5. 篡改归档被拒绝。
6. Windows 只读属性和 mtime 能恢复。
7. 全部自动化测试通过。

## 8. 当前范围外功能

- 定时备份和历史版本淘汰；
- 实时目录监控；
- 网络备份和用户系统；
- 增量或块级备份；
- 特殊文件、所有者和 ACL 恢复；
- 流式超大文件处理；
- 暂停、取消、进度和速度显示。

# DBackup 需求分析说明书

## 1. 文档目的

本文档定义 DBackup 数据备份软件的功能范围、质量要求与验收标准，包括本地归档、筛选、自动化、网络服务和块级增量备份。课程评分项是外部基线；团队主动采用的安全与工程增强是产品基线；当前完成状态不在本文件中推断，统一记录在 `traceability-matrix.md`。

## 2. 项目背景

DBackup 是面向 Windows 10/11 的数据备份工具。用户可将多个文件和文件夹组合保存为单个 `.abk` 文件，或保存到本地/远程增量仓库，并恢复目录结构、内容和元数据。项目使用 C++17、Qt 6 Widgets、CMake、zlib、Windows CNG、SQLite 和 Google Test。

## 3. 用户与使用场景

主要用户包括手工备份资料的普通 Windows 用户、配置后台自动任务的用户、使用受信局域网服务器的远程用户，以及维护服务器证书和数据目录的管理员。

典型场景：

1. 用户选择一个或多个资料文件、文件夹和 `.abk` 保存位置，生成本地备份。
2. 用户输入密码，生成压缩且加密的备份文件。
3. 用户通过扩展名、路径、大小或日期排除不需要的数据。
4. 用户选择 `.abk` 或历史快照和目标目录，恢复备份内容。
5. 用户配置定时/实时任务和保留策略，让程序在系统托盘中持续运行。
6. 用户登录远程服务器，只上传缺失数据块，并在另一位置恢复自己的快照。

## 4. 功能需求

### FR-01 备份来源与目录扫描

- 系统应允许在一个备份任务中添加多个普通文件和文件夹。
- “添加来源”按钮应提供文件和文件夹两种入口；文件和文件夹选择均支持多选。
- 系统应递归扫描普通文件和目录。
- 系统应保留相对目录结构。
- 遇到无法访问的目录、无法读取的文件或重解析点时，系统应终止备份并给出错误，不得静默生成不完整备份。

### FR-02 打包备份

- 系统应将选中的目录树写入单个 `.abk` 文件。
- 归档应包含 Magic、版本、条目数量和条目数据。
- 归档写入应先写临时文件，完整成功后替换目标文件。
- 写入失败时不得以损坏文件覆盖原有有效备份。

### FR-03 数据还原

- 系统使用唯一的 `.abk` 格式创建和读取归档；格式标识不作为用户可配置或选择的概念。
- 系统应恢复普通文件、目录、文件内容、修改时间和可恢复的 Windows 文件属性。
- 系统应拒绝绝对路径、盘符路径、空路径和含 `..` 的路径。
- 单个文件应通过临时文件写入并原子替换。

### FR-04 压缩

- 当前 `.abk` 格式使用 zlib 尝试压缩每个非空文件。
- 仅当压缩结果小于原始数据时才保存压缩结果。
- 解压后应校验恢复数据的长度。

### FR-05 密码保护

- 用户可选择是否设置密码。
- 加密归档使用 PBKDF2-SHA256 派生 256 位密钥，并使用随机 Salt、Nonce 和 AES-256-GCM 加密认证归档正文。
- GCM 标签失败、错误密码、损坏或篡改必须中止恢复。

### FR-06 自定义筛选

GUI 应提供独立的可视化筛选配置窗口，不要求用户记忆或手写表达式。面板至少包含路径、类型、名称、时间、尺寸和用户六类条件，并在应用前检查格式和范围。类型提供常用文件类别预设，尺寸可选择 B/KB/MB/GB，时间提供今天、最近 7 天和最近 30 天快捷项，并提供临时文件、系统缓存、编译输出和日志文件的常用排除选项及扫描预览。

筛选表达式由分号分隔的 `key=value` 组成，支持：

| 键 | 含义 | 示例 |
|---|---|---|
| `path` | 相对路径包含指定文本 | `path=docs` |
| `name` | 名称包含指定文本 | `name=report` |
| `ext` | 文件扩展名 | `ext=.txt` |
| `type` | `file` 或 `dir` | `type=file` |
| `minsize` | 最小字节数 | `minsize=1024` |
| `maxsize` | 最大字节数 | `maxsize=10485760` |
| `after` | 不早于指定日期 | `after=2026-01-01` |
| `before` | 不晚于指定日期当天 | `before=2026-12-31` |
| `owner` | 所有者名称包含文本 | `owner=alice` |

未知键、非法数字、非法日期、错误类型和矛盾范围应在操作开始前提示用户。

### FR-07 图形界面

- GUI 应采用可扩展的主窗口导航，至少包含概览、备份、还原，并为任务计划、历史版本、存储后端和设置保留独立模块位置。
- 用户可通过现代 Windows 系统对话框选择多个文件或文件夹，并在列表中移除来源。
- 密码输入应隐藏字符。
- 筛选条件应通过“配置筛选”窗口填写，并在主界面显示当前筛选摘要。
- 操作应在后台线程执行，完成后在日志区显示结果。
- 必填路径未选择时，操作按钮应不可用。

### FR-08 归档格式一致性

- 所有打包入口都应生成同一种格式。
- 归档格式由程序内部管理，GUI 和用户文档不提供格式版本选择、转换或迁移操作。

### FR-09 自动化

- 用户可创建定时或实时备份任务，设置来源、仓库、Cron、筛选、保留数和启停状态。
- 同一任务不得并发执行；执行期间的实时变化应合并为后续执行。
- 密码存入 Windows 凭据管理器，不得明文写入任务配置。
- 任务配置只读取当前 schema 版本；不自动迁移旧配置。

### FR-10 增量仓库

- 文件按 4 MiB 分块，块标识为明文 SHA-256，相同块只存储一次。
- 块和清单应加密认证；快照只在所有块可用后原子提交。
- 用户可列出、恢复、删除快照并执行保留策略。
- 仓库初始化不得将无效或损坏的已有仓库当作新仓库覆盖。

### FR-11 网络备份

- 服务器应使用 TLS、PBKDF2 密码哈希和有时效的 Bearer Token。
- 快照、块和查询必须按账户隔离。
- 客户端上传前查询缺失块，断线后可继续上传或下载。
- 首次连接自签名证书时应由用户核对 SHA-256 指纹；指纹变化时必须阻止连接。

### FR-12 进度和取消

- 耗时操作应显示阶段、当前项目、文件数、字节数、速度和预计剩余时间。
- 取消后不得生成可见的不完整归档或快照。

## 5. 非功能需求

### 正确性

- 恢复后的文件内容应与源文件逐字节一致。
- 错误或损坏归档不得被当作有效归档恢复。

### 健壮性

- I/O 错误必须返回明确错误信息。
- 不得静默跳过无法读取的数据。
- 临时文件应在失败后清理。

### 易用性

- README 应提供构建、使用、筛选和测试说明。
- 错误信息应指出失败对象和原因类别。

### 安全性

- 解包不得写出目标目录。
- 密码密钥应使用随机 Salt 和足够次数的 PBKDF2。
- 加密备份使用 AES-256-GCM 认证加密，不提供降低安全性的解密模式。

### 可维护性

- 核心归档逻辑与 GUI 分离。
- 使用自动化测试保护归档格式和核心行为，并验证无效格式被明确拒绝。

### 可审计性

- 每项 P0/P1 需求必须映射到设计模块和验收用例。
- `PASS`、`FAIL`、`SKIP`、`BLOCKED` 和 `MANUAL` 必须按实际证据记录，不能把未执行项目记为通过。
- 功能行为改变时，同一提交应同步更新需求、设计、追踪矩阵和测试。

## 6. 数据与元数据范围

当前版本支持普通文件、目录、符号链接、Junction、时间、Windows 属性和安全描述符。属主和 ACL 恢复受当前账户权限和目标文件系统能力限制。

## 7. 验收标准

1. 项目能在 Windows + MinGW 环境使用 CMake 构建。
2. 普通文件、空文件、二进制文件和嵌套目录能完成备份还原。
3. 程序生成的归档均可读取，伪造或无效格式被明确拒绝。
4. 压缩、加密、错误密码和筛选场景通过自动化测试。
5. 篡改归档被拒绝。
6. Windows 只读属性和 mtime 能恢复。
7. 全部自动化测试通过，跳过项具有明确的权限或平台原因。
8. `.abk`、本地增量、计划/实时和 localhost TLS 远程流程均完成一次端到端验收。
9. 便携 ZIP 在未安装 Qt 和编译工具的 Windows 10/11 电脑上能够启动并完成基础备份恢复。
10. 需求、设计、测试用例和结果可通过 `traceability-matrix.md` 追踪。

## 8. 产品边界

- 不提供可直接暴露到公网的托管服务、多节点高可用或密码找回。
- Windows 设备对象和活动命名管道不是可持久化普通文件，程序应拒绝而不是伪造恢复结果。
- 不支持 Linux、macOS 和非 NTFS 文件系统上的完整 Windows ACL 语义。

## 9. 需求来源、开发顺序与追踪

- 课程基础要求：数据备份、数据还原、可用软件及需求/设计/测试文档。
- 课程扩展项：特殊文件、元数据、六类筛选、打包、压缩、加密、GUI、定时、实时、网络、用户、服务器元数据、传输加密和增量。
- Sprint 1-5 的任务分解、完成定义、风险和推荐实施顺序见 `development-guide.md`。
- 课程评分项到代码模块和测试编号的映射、以及当前差距见 `traceability-matrix.md`。
- 课程指出扩展功能若由第三方库或程序直接实现，相关扩展分可能折半；答辩前应确认口径，并说明项目自主完成的格式、集成、错误处理和测试工作。

# DBackup 需求-设计-测试追踪矩阵

## 1. 状态口径

本矩阵用于防止需求、实现和测试相互脱节。状态只反映当前仓库中可见的实现与证据，不代表最终验收结论。

| 状态 | 含义 |
|---|---|
| 已自动验证 | 有自动测试且最近结果通过 |
| 已实现待人工验收 | 存在实现，但需要 GUI、权限、网络或双机证据 |
| 部分实现 | 主路径存在，但仍缺课程要求中的关键分支或测试 |
| 未实现/未发现 | 审查中未找到可靠实现，应进入 backlog |
| 环境阻塞 | 功能或测试需要管理员、开发者模式、第二台电脑等 |

## 3. 优先修复队列

### P0：影响正确性或安全

1. 恢复路径链重解析点检查和危险链接覆盖。
2. 远程下载块在缓存前的格式、GCM 和 SHA-256 验证。
3. 服务器 Token 过期、用户隔离和快照引用事务集成测试。
4. 失败/取消不得发布归档或清单，已有有效版本不得受损。

### P1：课程评分闭环

1. 硬链接组保存与恢复。
2. 六类筛选逐类 GUI 和恢复集合证据。
3. 自动任务完整编辑、启停和立即运行；失败保留；实时溢出重扫和目录丢失后的重试。
4. localhost TLS 的注册、上传、历史、恢复和删除全流程。
5. 增量快速路径、保留策略和引用清理证据。

### P2：产品和答辩质量

1. 历史搜索、容量、逻辑/物理大小和保留预览。
2. 统一速度/ETA、所有阶段取消和更清晰错误建议。
3. Qt offscreen 测试、发布文案扫描、干净电脑便携包验证。
4. 正式性能数据、代码覆盖率和长时间后台运行记录。

## 4. 更新规则

- 新需求先分配编号和验收用例，再开始编码。
- 状态变为“已自动验证”必须附测试名和最新结果；人工验收必须附证据路径。
- 实现被删除或行为变化时，同一提交更新需求、设计、矩阵和测试。
- 任何 P0/P1 的 `FAIL`、`BLOCKED` 或未实现项都必须在最终报告中解释，不得从表中删除。
